# Cyrene Approval & Eval Issue Tools

面向 Cyrene 工作台的 Go 插件，提供审批变更说明、评测工单草稿和工单修复复核。三个工具都支持 stdio MCP 和单次 JSON 命令行调用。

## 插件功能

### 审批变更说明

`cyrene_explain_approval` 根据同一资源的前后快照，生成一份供审批人查看的变更说明。

- **输入**包括操作类型、工作区、目标资源、预期修订号，以及变更前后的参数和修订号。流水线操作可以附上流水线 ID。
- **差异**按字段路径列出新增、删除和修改项，分别给出变更前后的值，并遮盖常见凭据字段。预期修订号与前置快照不一致时，调用方需重新读取资源并生成预览。
- **输出**包含摘要和结构化明细。接入 Navigator 后，差异作为调用方的变更预览显示在审批卡片上，审批人可以展开查看并作出决定。

### 评测工单草稿

`cyrene_draft_eval_issues` 读取一次已完成的 Echo 评测，为成组出现的失败生成 GitHub Issue 草稿。

- **分组**按评测器和失败表现聚合样本，例如输出缺失、类型不匹配或得分低于阈值。
- **查重**在配置的 GitHub 仓库中搜索分组指纹及相关 Issue。找到打开的匹配工单时，建议补充证据，并标注本次查重是否完整。
- **输出**为包含失败数量、模型引用、样本证据和复核建议的 Markdown 草稿，同时标记样本读取是否截断。草稿由使用者确认并提交。

### 工单修复复核

`cyrene_review_eval_fix` 比较修复前后两次已完成的 Echo 评测，生成可附到原工单的复核报告。

- **输入**为基线和候选评测 ID。也可以指定原 Issue、失败分组指纹或候选模型引用。
- **核对**两次评测的套件、执行绑定和评测器，再按样本序号或稳定样本 ID 配对。两次评测使用不同输入制品时，会核对测试输入和参考答案。
- **输出**将样本分为恢复、仍失败、新增失败、仍通过和不可比较五类，并记录无法比较的原因及样本覆盖范围。

直接调用插件时，可以用 `useAI` 请求额外解读。审批工具向模型提供差异路径和操作类型，评测工具提供汇总元数据。差异计算、Issue 查重和样本比较由插件处理。

## 快速体验

需要 Go 1.25 或更新版本。在仓库根目录运行以下命令，可查看示例中训练轮次从 `2` 调整为 `3` 的审批差异。

```sh
go build -buildvcs=false -o bin/cyrene-tools ./cmd/cyrene-tools
./bin/cyrene-tools explain-approval < examples/approval.json
```
